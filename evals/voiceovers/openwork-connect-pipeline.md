# OpenWork Connect capability pipeline

Cast is Alex, the Acme Robotics admin, proving that an organization MCP server becomes a live OpenWork Cloud capability for the desktop agent without a copied catalog.

1. "An admin adds any MCP server to the organization by name and URL — this one is a live tool server the team already uses."

2. "OpenWork doesn't copy a catalog. The moment the server gains a new tool, search sees it — no re-sync, no admin step."

3. "On the desktop, signing in is all it takes: OpenWork Cloud injects one connection with exactly two tools — search and execute."

4. "The agent is steered to search first. A plain-language request finds the org's tool, ranked beside native Google Workspace capabilities."

5. "Execute runs the real tool as this member, through the organization's connection — the external server's own log proves the call."

6. "Access is the boundary: revoke the grant and the tool vanishes from search; an unconnected teammate sees a fix-it hint instead of a broken tool."

7. "Sign out and nothing leaks: the connection stays parked, no new tokens are minted, and the next sign-in brings it back to life."
